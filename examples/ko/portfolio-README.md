# 클라우드베리 실습 포트폴리오

비정형 회의 메모와 고객 문의를 실행 가능한 문서로 바꾸고, 실제로 지저분한 주문 데이터를 진단·정제·검증했으며, 같은 내용을 웹 초대장과 이메일 뉴스레터로 구현했습니다. 또한 구체적인 기획안을 재사용 가능한 템플릿으로 전환하면서 확인되지 않은 정보는 가정 또는 TBD로 분리해, 결과물을 만드는 능력뿐 아니라 검토·재사용·설명 가능성을 함께 갖춘 업무 방식을 보여줍니다.

## 파일 안내

| 파일 | 무엇인지 | 랩 | 한 줄 설명 |
|---|---|---|---|
| `README.md` | 포트폴리오 인덱스 | 보너스 랩 B3 — 정리는 에이전트에게 | `my-work/`의 산출물과 학습 결과를 한눈에 찾을 수 있게 정리한 안내서 |
| `minutes.md` | 회의록 | Lab 1 — 낙서 메모에서 회의록으로 | 불확실한 결정은 TBD로 남기고 참석자·결정·액션·미결 질문을 구조화한 회의록 |
| `cs-reply-draft.md` | 고객 답장 초안 | Lab 2 — 답장 하나, 목소리 셋 | 배송 지연과 오배송에 대해 사실만 사용해 두 가지 해결 옵션을 제시한 답장 |
| `cs-reply-template.md` | CS 답장 템플릿 | Lab 2 — 답장 하나, 목소리 셋 | 고객별 사실을 `{플레이스홀더}`로 교체해 재사용할 수 있는 발송 전 체크 포함 템플릿 |
| `orders-clean.csv` | 정제 주문 데이터 | Lab 4 — 엉망인 데이터 구조하기 | 날짜·도시·상품 표기를 통일하고 중복을 제거하되 판단이 필요한 행은 보존한 CSV |
| `orders-cleaning-report.md` | 데이터 정제 보고서 | Lab 4 — 엉망인 데이터 구조하기 | 컬럼별 문제, 변경 로그, 사람 판단 항목과 검증 가능한 매출 계산을 기록한 보고서 |
| `invite.html` | 행사 웹 초대장 | Lab 5 — 내 문장이 웹페이지로 | 외부 라이브러리 없이 반응형·접근성을 고려해 만든 종이와 호박 팝업 원페이지 |
| `draft-brief.md` | 로열티 카드 기획안 | Lab 6A — 템플릿 공장·기획 트랙 | 5회 구매 보상 프로그램의 대상·범위·측정 신호·리스크를 한 페이지로 정리한 브리프 |
| `template-brief.md` | 기획 브리프 템플릿 | Lab 6A — 템플릿 공장·기획 트랙 | 사례 내용을 `{플레이스홀더}`로 바꿔 다른 프로그램에도 재사용할 수 있게 만든 구조 |
| `newsletter.html` | HTML 이메일 뉴스레터 | 보너스 랩 B2 — 메일함에서 살아남는 이메일 | 600px 표 기반 레이아웃과 인라인 스타일로 제작한 이메일 클라이언트 안전 뉴스레터 |
| `style-tile.html` | 시각 언어 스타일 타일 | 역할별 플레이북 — 디자인 | 접근성 검증 팔레트, 14~40px 시스템 타입 스케일과 버튼 상태를 한 페이지에 정리한 기준 |
| `close-kit.md` | 월간 판매 마감 키트 | Lab 7 — 캡스톤·재무/운영 미션 | 원본 보존부터 데이터 점검, 재사용 수식, 월간 요약과 승인까지 동료가 단독 수행할 수 있게 만든 런북 |
| `dashboard-spec.md` | 주문 대시보드 사양 | 보너스 확장 — 데이터 대시보드 | 세 비즈니스 질문별 지표 계산식·차트·필드와 데이터로 답할 수 없는 범위를 명시한 설계서 |
| `sql-examples.md` | 주문 분석 SQL 모음 | 보너스 랩 B1 — SQL 맛보기 | 상품 매출, 채널 주문 수, 반복 고객을 구하는 세 쿼리와 쉬운 설명을 담은 예제 |
